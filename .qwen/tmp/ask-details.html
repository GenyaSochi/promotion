Пояснение к вариантам оформления сайта

Я проверил файлы проекта. Я не менял файлы проекта. Я не выбираю вариант за вас.

Основа вопроса

Вы попросили оформить весь проект в стиле блоков «Наши услуги».

Этот стиль есть в шести блоках на главной странице.

Другие страницы используют иной вид. Там есть центрированные заголовки и блоки с рамками.

Перед правкой нужно выбрать направление. Для этого подготовлен статический прототип.

В прототипе четыре варианта. Ниже они названы по порядку.

Проверенные сведения

  1. nuxt.config.ts подключает шрифт Inter. Веса: 400, 500, 700, 800.
  2. nuxt.config.ts подключает стили в таком порядке: reset.css, style.css, css/main.css.
  3. app/assets/style.css задаёт шрифт Plus Jakarta Sans для body.
  4. app/assets/style.css задаёт Inter для классов .web-dev-hero-title и .web-dev-hero-subtitle.
  5. app/pages/index.vue содержит шесть блоков услуг. Они используют классы .web-dev-hero, .web-dev-hero-title, .web-dev-hero-subtitle и .web-dev-divider.
  6. app/pages/services/index.vue использует заголовок .hero, сетку .services-grid и блоки .service-card.
  7. app/pages/services/[slug].vue использует .hero, .service-detail-grid, .service-features-list и .cta-card.
  8. app/pages/web.vue использует .web-hero, .web-features-grid, .web-feature-card и .web-cta-card.
  9. app/pages/privacy.vue и app/pages/terms.vue содержат документы с разделами и списками.
  10. app/layouts/default.vue добавляет шапку, подвал и кнопку на каждой странице.
  11. app/assets/css/main.css содержит общие классы .section-header, .card, .feature-card и .service-card.

Проверка шла по коду. Я не открывал страницы в браузере. Я не проверял вид на всех ширинах экрана.

Смысл первого варианта

Название: чистая типографика.

Условие: цель — полное совпадение с блоками «Наши услуги».

Действие: убрать центрированные заголовки и блоки с рамками.

Оставить крупный заголовок, подзаголовок и волну.

Каждая страница станет последовательностью текстовых блоков.

Смысл второго варианта

Название: пронумерованная последовательность блоков.

Условие: нужен заметный ритм на всех страницах.

Действие: поставить номер перед каждым блоком.

Сохранить волны между блоками.

Смысл третьего варианта

Название: крупный заголовок и колонки без рамок.

Условие: нужно сохранить сетки.

Действие: убрать рамки и фон карточек.

Оставить колонки и акцентные линии.

Смысл четвёртого варианта

Название: общие параметры оформления.

Условие: нужно минимальное изменение.

Действие: заменить шрифт на Inter.

Привести кнопки к овальной форме.

Убрать жёсткие рамки.

Различия

  • Первый вариант меняет разметку сильнее всего.
  • Четвёртый вариант меняет разметку меньше всего.
  • Первый и второй варианты убирают карточки.
  • Третий вариант сохраняет колонки.
  • Четвёртый вариант сохраняет структуру страниц.
  • Первый вариант даёт один вид для всех страниц.
  • Четвёртый вариант оставляет различия между страницами.

Влияние и риски

  • Правки затронут страницы и компоненты.
  • При первом варианте длинные документы могут стать труднее для чтения.
  • При втором варианте номера нужны на всех страницах.
  • При третьем варианте часть карточек останется.
  • При четвёртом варианте сходство с блоками услуг будет частичным.
  • После правок запустите npm run build.
  • После сборки проверьте страницы на узком экране.

Рекомендация

Если цель — полное совпадение со стилем «Наши услуги», выберите первый вариант.

Причины:

  1. Он повторяет классы .web-dev-hero-title и .web-dev-hero-subtitle.
  2. Он убирает блоки с рамками, которые отличают страницы от услуг.
  3. Он даёт единый ритм для главной, услуг и других страниц.

Документы privacy.vue и terms.vue оставьте в обычном виде.

Это действие сохранит удобство чтения.
